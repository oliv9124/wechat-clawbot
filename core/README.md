# core：所有机器人共用的程序

每个机器人的进程都以自己的目录（`bots/<名字>/`）作为工作目录启动，`core/` 里的程序从工作目录读这个机器人的 `config.json`、`MEMORY.md`、`tasks.js`、`topics.json`，运行数据写进它的 `data/`。

## 模块

| 文件 | 职责 |
| :--- | :--- |
| `routine_server.js` | 按顺序处理收件箱里的消息，调用智能体（`agy`）生成回复，发送文字、图片、视频卡片和文件。等待期间每 20 秒重发"正在输入"，90 秒还没结果就先回一句"在后台接着弄"；长任务占着主会话时，新消息改用临时会话。也处理「清除记忆」「记忆改动」「撤销记忆 N」 |
| `wechat_forwarder.js` | 长轮询微信 iLink，只接收绑定用户的消息，下载解密图片、语音、文件后写进收件箱 |
| `inbox.js` | 收件箱 `data/inbox/`：先落盘再处理，进程重启或崩溃都不丢消息 |
| `wechat_reply.js` | 微信 iLink 通信：发文字、"正在输入"、图片、视频卡片和文件；读写配置和运行状态（原子写入） |
| `scheduler.js` | 定时任务（`tasks.js`）、随口提醒（`data/reminders.json`）、凌晨 3 点整理昨天的聊天、存记忆版本、早间"记忆变动" |
| `memory_config.js` | 记忆的公共设置：专题配置、"会话已重置"标记、长度上限 |
| `memory_history.js` | 记忆历史：存版本、生成"记忆变动"汇报、按条撤销；也是命令行工具（见下） |
| `ai_copy.js` | 给 `tasks.js` 用的文案生成（`callAiCopy`），最多等 90 秒 |
| `weather.js` | 实时天气（Open-Meteo，不需要 Key），拿不到就如实说 |
| `login.js` | 扫码绑定微信：只有扫码的那个微信能使用机器人 |
| `agent_health.js` | 判断每次调用智能体的结果（成功 / 登录失效 / 超时 / 出错），记到 `data/state/agent_*.json` 供告警使用 |
| `alert.js` | 各进程把出的问题记到 `data/alerts/`，由监控统一去重、发送；只记问题类型和原因，不记消息内容 |
| `monitor.js` | 告警监控：检查所有机器人，经各自的微信（和邮件）通知 |
| `send_mail.py` | 发告警邮件（Python 自带 smtplib），授权码从标准输入传入 |

## 记忆

- `MEMORY.md` 每条消息都带上，上限 3000 字；`data/memory/topics/` 下的专题分卷每个上限 8000 字。小的专题每条消息都带（从小到大放，合计 4000 字以内），放不下的大专题在这条消息或之前两条用户消息里提到 `topics.json` 里的关键词时才带。超过上限照常全部带上，超过两倍才截断。
- 凌晨 3 点整理昨天的聊天：昨天没聊天就跳过；全天对话按 12000 字一段分段整理（最多 8 段），每段都重新读一遍当前记忆；整理在后台跑，不耽误定时任务和提醒。
- 记忆历史：调度器每分钟检查一次，记忆文件有改动、并且 2 分钟没再动，就存一版到 `data/memory-history/<名字>/`（git 库，需要装 git），标明是"聊天时"还是"凌晨整理"改的。`tasks.js` 里标了 `memoryDigest: true` 的任务后面附上"记忆变动"；没发出去就留到下一次一起列。
- 微信里：「记忆改动」看完整清单，「撤销记忆 2」「撤销记忆 1 3」「撤销记忆 全部」按条撤销。这几句由程序直接处理，不经过智能体，回复不写进聊天记录；那段内容后来又改过就不撤，并说明原因。
- 命令行：`node core/memory_history.js log <名字>` 看版本，`show <名字> <版本>` 看那一版改了什么，`restore <名字> <版本|YYYY-MM-DD>` 把记忆整体恢复到那一版（恢复前后都会存一版）。
- 设环境变量 `CLAWBOT_MEMORY_MODE=off` 可以关掉记忆历史。

## 告警

- `monitor.js` 每 30 秒检查一次 `bots/` 下所有机器人：各进程记下的问题（微信登录过期、定时任务或提醒没发出去、凌晨整理失败、消息处理失败、回复没发出去、存记忆版本失败）、智能体登录失效或连续失败、调度器没有心跳、定时任务到点没发；用 systemd 托管时还会检查服务是否反复崩溃或停了。
- 每个机器人的问题经它自己的微信发给它的用户。同一问题 6 小时内只通知一次，一直没好的过了 6 小时再提醒，恢复时发"已恢复"。机器人自己登录过期时发不了微信，配置了邮件就只发邮件。
- 配置（可选）：项目目录的 `alert.json`（或 `/etc/clawbot/alert.json`），`dedupe_hours` 是去重窗口，邮件部分用 `bash deploy/set_alert_email.sh` 填写。测试：`node core/monitor.js --test`（只测一个渠道加 `wechat` 或 `email`）。

## 进阶：一台机器上统一管理

默认每个机器人自己管自己。如果你用 systemd 托管、给每个机器人单独的系统账号和沙箱，还可以让一个"主人的机器人"（以 root 运行）统一管理：

- 在告警配置里写 `"owner_bot": "<主人机器人的目录名>"`：所有告警都经它发给主人；它管理所有机器人的记忆历史（存在只有 root 能读写的 `/var/lib/clawbot/memory-history`），主人还能用「<名字>记忆改动」查看、撤销其他机器人的改动。
- 其他机器人的服务里设 `CLAWBOT_MEMORY_MODE=managed`：它们读不到记忆历史，由主人的机器人把各自的"记忆变动"放进它们自己的目录，它们的早间播报附上（不编号、不能撤销）。
- 上线时 `node core/memory_history.js import-baseline <项目目录>` 以 git 里提交过的版本作为起点。
