# WeChat ClawBot：微信里的个人 AI 助手

基于腾讯官方的微信 iLink 协议，接入 Google Antigravity CLI（`agy`）。在微信里直接和它聊天，它能联网查资料、写代码、处理图片和文件、下载并总结短视频，还会按时给你发天气和提醒，并且记得你说过的事。

一台机器上可以跑任意多个机器人，**每个机器人完全独立**：各自的微信、人设、记忆、定时任务和运行数据，都在 `bots/<名字>/` 这一个目录里。

---

## 能做什么

- 💬 **对话**：多轮会话，回「清除记忆」开一个全新的会话（长期记忆保留）。
- 🎙 **语音、图片、文件**：语音自动转文字；图片和截图直接看；文件可以收也可以发。
- 🎬 **短视频**：抖音、B站、小红书链接，下载原画、以微信原生视频卡片发回来，还能提取逐字稿并总结要点。
- ⏰ **定时播报和随口提醒**：早间天气、午餐、早睡这类定时消息写在 `tasks.js`；随口一句"10 分钟后提醒我喝水"就会准时提醒。
- 🧠 **长期记忆**：人设和偏好写在 `MEMORY.md`，按主题的笔记放在专题分卷里；每天凌晨把昨天的聊天整理进长期记忆。
- 🕘 **记忆历史**：记忆的每次改动都存一版。早间天气后面附上"记忆变动"，告诉你昨天记住、改了什么；回「撤销记忆 2」就能撤掉第 2 条。
- 📥 **不丢消息**：收到的消息先落盘再处理，进程重启后接着处理；同一个会话不会被两件事同时使用。
- 🚨 **告警（可选）**：微信登录过期、智能体登录失效、服务崩溃、定时任务到点没发……经这个机器人自己的微信通知你，也可以同时发邮件。

## 目录结构

```text
├── install.sh                # 检查环境、安装依赖、准备 starter-bot
├── ecosystem.monitor.cjs     # 可选：告警监控（PM2，一台机器一个）
├── AGENTS.md / GEMINI.md     # 给智能体的规则（联网核实、视频发送、提醒、进程安全等）
├── scripts/new_bot.sh        # 新建一个机器人
├── deploy/set_alert_email.sh # 可选：配置告警邮件
├── core/                     # 所有机器人共用的程序（说明见 core/README.md）
├── skills/                   # 技能：短视频下载与文案提取、小红书
└── bots/
    ├── README.md             # 机器人目录的说明
    └── starter-bot/          # 第一个机器人（也是新建机器人的模板）
```

## 快速开始

### 1. 准备环境

- Node.js 18 以上（推荐 22）、npm、git（记忆历史要用）
- Google Antigravity CLI（`agy`），并且已经登录：`agy -p "你好"` 能正常回答
- 可选：Python 3.10+（短视频下载和文案提取）、ffmpeg（视频卡片的封面和时长）

然后在项目目录执行：

```bash
bash install.sh
```

它会检查上面这些、安装 PM2 和 `core/` 的依赖，并把 `bots/starter-bot` 准备好（生成 `config.json`、`MEMORY.md`、`tasks.js`、`topics.json`，本地接口的密钥随机生成）。

> 建议用普通账号运行，不要用 root：智能体会以运行它的账号的权限执行命令。

### 2. 扫码绑定微信

```bash
cd bots/starter-bot
node ../../core/login.js
```

用手机微信扫码并确认。**只有扫码的这个微信能使用这个机器人**，别人发来的消息一律忽略。扫码成功后，先在手机微信的 ClawBot 对话里随便发一句话（比如"你好"），激活会话。

### 3. 启动

```bash
./start.sh
```

PM2 会在后台运行这个机器人的 3 个进程：`starter-bot-routine`（处理消息）、`starter-bot-forwarder`（接收微信消息）、`starter-bot-scheduler`（定时任务和提醒）。

```bash
pm2 status                      # 看状态
pm2 logs starter-bot-routine    # 看日志
pm2 startup                     # 开机自启（按它的提示执行一条命令）
```

## 个性化

| 文件 | 改什么 |
|---|---|
| `config.json` | `user_nickname`（它怎么称呼你）、`bot_name`（它叫什么）、`forbidden_persona`（不许用的称呼）、`port`（本地接口端口，多开时每个机器人不同） |
| `MEMORY.md` | 人设、你的偏好和需要它一直记得的事 |
| `tasks.js` | 定时任务：时间、文案、天气城市（改 `CITY` 的经纬度）。标了 `memoryDigest: true` 的任务后面会附上"记忆变动" |
| `topics.json` | 专题分卷：按主题存的长期记忆，文件在 `data/memory/topics/` |

改完 `tasks.js` 或 `config.json` 后执行 `./start.sh` 重新加载。

## 记忆

- **核心档案** `MEMORY.md` 每条消息都带上。上限 3000 字。
- **专题分卷** 在 `data/memory/topics/` 下，每个上限 8000 字。小的专题每条消息都带（合计 4000 字以内）；放不下的大专题，在这条消息或之前两条消息里提到关键词时才带。
- 你让它"记住"什么，它会写进去；每天凌晨 3 点再把昨天的全部聊天整理一遍（聊得多会分段整理）。
- **记忆历史**：每次改动都存进 `data/memory-history/`（需要 git）。在微信里：
  - 「记忆改动」：看最近的改动清单（带编号和内容）
  - 「撤销记忆 2」「撤销记忆 1 3」：按编号撤销；「撤销记忆 全部」：全部撤销
  - 那段内容后来又被改过时不会硬撤，会告诉你原因
- 服务器上：`node core/memory_history.js log starter-bot` 看版本，`node core/memory_history.js restore starter-bot 2026-10-01` 整体恢复到那天的版本。

## 多开

```bash
bash scripts/new_bot.sh work-bot        # 新建 bots/work-bot（端口自动选一个没用过的）
cd bots/work-bot
node ../../core/login.js                # 用另一个微信扫码
./start.sh
```

每个机器人的进程名都以目录名开头（`work-bot-routine` 等），互不冲突，数据也互不相干。

## 告警（可选）

```bash
pm2 start ecosystem.monitor.cjs && pm2 save
```

监控每 30 秒检查一次 `bots/` 下所有机器人，发现问题就经**这个机器人自己的微信**通知它的用户；同一个问题 6 小时内只通知一次，恢复时会说"已恢复"。

机器人自己的微信登录过期时它发不出微信，这种情况需要邮件：执行 `bash deploy/set_alert_email.sh` 按提示填写发信邮箱和授权码（写进项目目录的 `alert.json`，权限 600）。测试：`node core/monitor.js --test`。

## 常见问题

- **超过一天没给它发消息，它就不发提醒了？** 微信只允许机器人在你最近一次发消息后约 24 小时内主动发消息。快到时它会在消息末尾请你回一句；真的过了，提醒会先留着，你一回消息就补发。
- **微信登录过期**：在机器人目录执行 `node ../../core/login.js` 重新扫码。
- **智能体登录失效**（日志里有 Google 登录链接）：用运行机器人的账号执行 `agy -p "登录测试"`，按提示重新授权。
- **日志里看不到消息内容？** 默认不记录消息原文和令牌。排查问题时可以临时设环境变量 `CLAWBOT_LOG_CONTENT=1`。

## 安全

- 只有扫码绑定的微信能使用机器人；本地接口只监听 127.0.0.1，并且要带随机密钥。
- 微信里不能远程升级或重启程序，更新代码请在服务器上 `git pull` 后执行 `./start.sh`。
- 微信凭证、聊天记录、记忆都只存在你自己的服务器上，直连腾讯官方 iLink 节点。
- 进阶：可以用 systemd 托管，并给每个机器人一个单独的系统账号和沙箱（只能写自己的目录），这样一个机器人即使被诱导执行了危险命令，也碰不到其他机器人和系统。
